# RHFiles 0.1.45

## 中文

- 修复复制文件后粘贴到微信 / QQ 变成文本：之前复制时在剪贴板上同时放了一份文本格式（文件路径），聊天类程序优先读了它。现在只发布文件格式（CF_HDROP + 拖放效果），粘贴过去就是文件本身。新增后端测试断言"复制文件时不得发布文本格式"。
- 压缩默认名字改为按第一个选中项命名：多选时用第一个文件的名字（自动去掉扩展名），文件夹则直接用文件夹名；如果同名压缩包已存在，自动改成不重复的名字（如 `photo (1).zip`），不再叫笼统的 `archive.zip`，也不会覆盖已有压缩包。
- ESC 取消重命名后重新选中该文件，不再丢失选中状态。
- 拖拽移动 / 复制现在也支持左侧全部区域：目录树、收藏夹、快速访问、此电脑（各驱动器）、库、云存储、最近访问。拖到条目上会高亮目标，悬停在目录树里的文件夹上约 0.7 秒会自动展开，方便拖进更深的目录。
- 说明：把文件**拖出** RHFiles 到微信 / QQ 这类外部程序目前仍然只会给出文本（WebView2 的 HTML5 拖拽无法向系统提供真实文件）。复制后粘贴已经可以正常工作；如果需要拖出也是真文件，需要额外实现系统级 OLE 拖拽源，可以按需再做。

## English

- Fixed files becoming text when pasted into WeChat / QQ: copying also published a text format (the file paths) that chat apps preferred. Only file formats (CF_HDROP plus the drop effect) are published now, so pasting delivers the files. A backend test asserts that copying files must not publish a text format.
- The default archive name now follows the first selected item: the first file's name without its extension, or the folder name; if that archive already exists it is renamed to a unique one (for example `photo (1).zip`) instead of the generic `archive.zip`, and an existing archive is never overwritten.
- Cancelling a rename with Escape keeps the file selected.
- Drag move / copy now works across the whole sidebar: directory tree, favorites, quick access, This PC drives, libraries, cloud storage and recent. The hovered entry is highlighted, and hovering a collapsed tree folder for about 0.7 seconds expands it so deeper folders can be targeted.
- Note: dragging files **out** of RHFiles into external programs such as WeChat or QQ still delivers text only, because WebView2's HTML5 drag cannot expose real files to the system. Copy and paste works now; making drag-out deliver real files needs a native OLE drag source, which can be added on request.
