# RHFiles 0.1.25

## 中文

- 修复部分机器更新后启动界面长时间空白的问题：本地语言资源、已知文件夹、窗口状态与 Windows 集成初始化现在都有明确的等待上限；任一步骤异常都不会无限阻塞主界面，并会把具体阶段写入应用日志。若整个启动链仍未完成，界面会显示可重试的错误，而不是保持纯空白。
- 修复恢复标签页后文件列表可能一直空白的问题。尚未加载的标签现在显示路径和加载动画；后台读取加入独立的逐标签请求与 10 秒超时，失败时显示分类错误、技术详情和重试按钮。真正没有内容的目录会明确显示“此文件夹为空”。双窗格右侧使用相同的超时与错误处理。
- 版本记录改为分阶段加载：客户端内置的完整离线历史会先立即显示，服务器或 GitHub 的最新记录随后在后台合并。即使更新源离线、代理错误或网络请求超时，用户也能阅读内置记录并看到回退提示，不再面对持续 35 秒的空白加载区。

## English

- Fixed a startup path that could leave the interface blank for a long time after an update on some machines. Local language assets, known folders, saved window state, and Windows integration initialization now have bounded waits. A failed stage no longer blocks the main interface indefinitely and its exact stage is written to the application log. A final watchdog shows a retryable error instead of leaving a blank view.
- Fixed restored tabs that could remain silently blank. An unloaded tab now shows its path and a loading indicator; background reads use independent per-tab requests with a 10-second timeout and render categorized errors, technical details, and a retry action. A genuinely empty directory explicitly says that it is empty. The right side of dual-pane mode uses the same bounded behavior.
- Version history now loads progressively: the complete offline history bundled with the client appears first, then fresh entries from the server or GitHub are merged in the background. If the source, proxy, or network is unavailable, bundled notes remain readable with a fallback notice instead of a blank 35-second loading state.
