# RHFiles 0.1.56

## 中文

- **修好"密码明明正确却反复要密码、还说密码错误"**。原因有两层：
  - 判定过宽：只要 7-Zip 报告里有 `Sub items Errors`（**任何**条目失败都会出现，例如个别文件损坏），就被当成密码问题，于是重新弹密码框；
  - 重试前不再校验：弹框拿到的密码没有先验证就直接重试，导致正确密码也会被反复追问。
  现在只有真正的密码错误（`Wrong password` / `Password is incorrect` / 无法打开加密档案）才会弹框；**已经验证通过的密码不会再弹**，而是明确告知"解压未完全成功"。
- **失败信息改为可读的摘要**：不再是几万行输出，而是例如
  `7-Zip extraction failed (exit code 2): 48 entries failed: Wrong password ×48 (first: vamzhb\AddonPackages\A1X.A1X_Bear_Ears.1.var)`
  ——包含失败条目数、失败原因与第一个失败条目，便于直接判断是密码问题还是压缩包损坏。
- 新增提示文案：密码已确认正确、但部分条目无法解开时，说明"这些条目在压缩包中的数据可能已损坏，或使用了另一个密码，其余文件已解压完成"。
- 新增单元测试覆盖失败原因摘要的解析（多原因计数、首个条目、无错误时返回空），并给无头校验脚本补上 4 项回归断言（判定不再匹配通用错误、已验证密码不再弹框、部分解压文案与预览音量文案齐备）。

## English

- **Fixed the "the password is correct but it keeps asking and claims it is wrong" loop.** Two causes:
  - the check was too broad: any 7-Zip `Sub items Errors` summary (which appears whenever *any* entry fails, e.g. damaged files) was treated as a password problem and re-opened the prompt;
  - retries did not re-verify: a password typed into the prompt was retried without validation, so a correct password could be asked for again and again.
  Now only real password rejections (`Wrong password` / `Password is incorrect` / cannot open encrypted archive) prompt, and a password that already verified is never asked for twice — the user instead gets a clear "extraction was incomplete" message.
- **Failure details are now a readable summary** instead of raw output, for example
  `7-Zip extraction failed (exit code 2): 48 entries failed: Wrong password ×48 (first: vamzhb\AddonPackages\A1X.A1X_Bear_Ears.1.var)`
  — failing-entry count, reasons, and the first affected entry, which is what tells a password problem apart from a damaged archive.
- Added a message for the verified-password case: the listed entries could not be decrypted (their data in the archive is probably damaged, or they were added with a different password) while everything else was extracted.
- Added a unit test for the failure-reason summary (multiple reasons with counts, first entry, empty when there are no errors) and four regression assertions to the headless verification script (broad match removed, verified passwords never re-prompt, partial-extract and preview-volume strings present).
