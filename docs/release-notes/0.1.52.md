# RHFiles 0.1.52

## 中文

- **加密压缩包现在在解压前就询问密码**，不再等整整一轮解压失败之后才弹框。右键「解压到当前文件夹」时会先做一次快速探测（只读压缩包目录，几秒钟），发现加密条目就立即弹出密码框；101 GB 这种规模的包不会再让你白等一轮。
- **密码当场校验**：输入后先用包里**最小的加密文件**做一次快速解密测试（`7z t`，通常瞬间完成），密码不对立刻重新询问，而不是先跑一遍完整解压再报错。
- 双击进入压缩包浏览时的「全部解压」同样先校验密码；单个文件解压保持原样（本身就会快速失败并重试）。
- 新增后端命令 `archive_encryption_probe`（返回最小的加密条目，`None` 表示无加密）与 `verify_archive_password`（单条目密码校验），并新增单元测试覆盖：最小加密条目挑选、无加密包探测返回空、中文密码包的正确/错误密码校验。
- 说明：0.1.50/0.1.51 其实已经有密码重试逻辑，但它挂在"解压失败"之后，对这个 101 GB 的分卷包等于要等一整轮失败；本版本把询问提前到解压开始之前。

## English

- **Encrypted archives now ask for the password before extracting**, instead of only after a full failed pass. Right-click "Extract here" first runs a fast probe (central-directory read only, a couple of seconds) and prompts immediately when encrypted entries are found — no more waiting out a 101 GB attempt.
- **The password is verified on the spot**: the smallest encrypted member is test-decrypted first (`7z t`, usually instant), so a wrong password re-prompts right away instead of after a complete failed extraction.
- "Extract all" from the archive browser verifies up front too; single-entry extraction stays as-is (it fails fast on its own and retries).
- Added backend commands `archive_encryption_probe` (returns the smallest encrypted entry, `None` when the archive is not encrypted) and `verify_archive_password` (single-member password check), with unit tests for picking the cheapest encrypted member, probing a plain archive, and verifying correct/wrong passwords on a Chinese-password archive.
- Note: 0.1.50/0.1.51 already had password retry logic, but it ran only after a failed extraction — for a 101 GB split archive that meant waiting out a full pass. This release moves the prompt before extraction starts.
