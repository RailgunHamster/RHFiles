# RHFiles Windows 0.1.96

1. RHFiles 设备路径的“复制路径”默认生成简短可读的 `rh://设备名/共享名/路径`，文件、文件夹、标签页、空白处菜单和 Ctrl+Shift+C 使用相同规则。多选一行一个，本地磁盘与 SMB 路径保持原样。
2. 设备重名时自动带上组名，如 `rh://RH@WINSERVER/C/Downloads`。组名和设备名仍有歧义、设备已移除或本机记录变化时明确报错，整批不改剪贴板，不猜测目标，也不悄悄复制长 ID。生成短地址只读取本机组记录，不连接网络、不自动重试。
3. 标签页悬停卡片改为“设备名/路径”，不再显示内部组和设备 ID。内部收藏和标签页仍保存稳定身份地址，不受改名、IP 变化影响。
4. 设置的“设备组 → 连接诊断”可显式复制当前路径或诊断记录中设备根目录的稳定地址。增加 `files.copyPaths`、`devices.address` 和 `devices.copyStableAddress` 自动化接口，与界面共用逻辑。

短地址依赖设备名称，改名后旧短地址可能失效。地址本身不授予访问权限，也不是入组邀请。

## English

1. Copy Path now defaults to readable `rh://device/share/path` addresses across file, folder, tab and background menus and Ctrl+Shift+C. Multiple paths use one line each; local and SMB paths retain their original syntax.
2. Duplicate device names are qualified by group, such as `rh://RH@WINSERVER/C/Downloads`. Remaining ambiguity, removed records or concurrent local-state changes fail the entire copy without changing the clipboard, guessing a target or falling back to internal IDs. Formatting only reads local membership records, without network probes or automatic retries.
3. Tab hover cards show the device name and path instead of internal group/device IDs. Stored favorites and tabs still use stable identity paths across renames and IP changes.
4. Device-group Connection diagnostics offers explicit stable-address copying for the current folder and recorded device roots. Added `files.copyPaths`, `devices.address` and `devices.copyStableAddress` APIs using the same UI workflow.

Readable addresses depend on device names, so an old address may stop resolving after a rename. Addresses are not invitations or access credentials.
