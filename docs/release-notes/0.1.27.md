# RHFiles 0.1.27

## 中文

- 修复开启实验性“Windows 文件对话框 / Explorer 集成”后原生 IPC 主线程死锁的问题。此前一旦伴随位置列表被创建，目录读取、标签切换、版本记录和更新检查会一起停止响应，并在超时后显示“无法打开此位置”；现在伴随窗口的创建与销毁会在异步命令执行器中完成，不再阻塞 RHFiles。
- 统一前后端命令参数命名：窗口状态恢复与保存、新窗口初始路径、Windows 资源管理器打开目标等参数现在使用 Tauri 要求的 camelCase。兼容层会仅转换旧扩展或旧调用的顶层 snake_case 参数，不会改写文件信息等嵌套数据。
- 左侧直接导航现在也有 10 秒等待上限；目录失败会把路径、原始错误和左右窗格来源写入应用日志，原生 IPC 拒绝同样会记录具体命令，避免再次只留下空白界面或笼统错误。
- 新增真实 GUI 回归：测试会实际开启 Windows 伴随位置列表，然后连续读取目录、窗口标签和完整离线版本记录，确保集成功能不能再次拖死更新与文件浏览。

## English

- Fixed a native IPC event-loop deadlock triggered when the experimental **Windows file dialog / Explorer integration** was enabled. Creating the companion location picker previously stopped folder reads, tab navigation, release history, and update checks together, eventually showing “Couldn't open this location.” Picker creation and destruction now run on the asynchronous command executor and no longer block RHFiles.
- Standardized frontend/backend command argument names. Window-state restore/save, new-window initial paths, and Windows Explorer target hints now use the camelCase names required by Tauri. A compatibility layer converts only top-level snake_case keys from older calls or extensions and leaves nested file data unchanged.
- Direct navigation in the left pane now has the same 10-second bound as background and right-pane loads. Navigation failures log the path, original error, and pane, while rejected native calls record their command name, preventing another silent blank view or generic-only failure.
- Added a real GUI regression that enables the Windows companion picker and then repeatedly reads a directory, the window label, and the complete offline release history, ensuring the integration cannot freeze browsing or updates again.
