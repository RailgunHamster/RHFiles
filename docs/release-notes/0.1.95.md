# RHFiles Windows 0.1.95

1. 补齐 RHFiles 设备文件的重命名、新建文件夹/模板文件、批量重命名、删除、属性、大小/哈希及空间分析，沿用普通文件菜单、快捷键和自动化接口。目录合并不删除目标文件夹，同名文件仍需要明确冲突选择。
2. 同一共享内移动直接使用服务端条件重命名；批量重命名支持名字互换，并保留中断恢复记录。源或目标被换成同名新对象后，旧操作不能继续覆盖、删除。
3. 未覆盖的复制、移动、合并加入安全撤销/重做。撤销复制时检查完整子树，新增文件或对象被替换会拒绝删除；重做源变化也会拒绝。远端删除与 SMB 一样不进入本机回收站。旧服务缺少版本证明时不伪造可撤销记录。
4. 远端压缩包支持浏览、密码验证、分卷、真实冲突检查和解压；压缩、媒体转换、Markdown 生成为 PDF 通过独立工作区处理并提交远端输出。RDP 剪贴板的虚拟文件先安全复制为临时输入，上传失败不删除原文件。
5. Windows 程序可接入已授权的可信 HTTPS WebDAV 路径；修复 HTTP/2 缺少 Host 头时重命名误报跨服务器错误。带匹配版本/独占锁的保存可以更新原文件，盲目覆盖仍拒绝；授权依附设备组，撤销后不能自动申请回来。缺少系统组件或兼容入口时，单文件保留为工作副本，编辑后可检查版本保存或另存，不静默丢弃修改。
6. 文件操作检查绕过浏览目录缓存；上传对象证明来自实际提交句柄，避免对后来同名的新文件建立错误的撤销记录。任务保留真实进度、取消和失败原因，不自动重放失败写入。
7. WebDAV 配置同步增加 RHVideo 服务器地址和用户名，不同步密码、令牌或会话，不覆盖当前登录。两端同时修改时显示冲突；含此信息的同步格式需要各端升级。

Windows 本地程序接入仍受 WebClient 与服务器文件系统能力限制；RHFiles 不安装驱动、不弱化 TLS、不伪造远端 ACL/备用数据流。符号链接、重解析点不跟随，目录不整体覆盖。客户端和提供文件的电脑都应更新。

## English

1. Added device-path rename, folder/template creation, batch rename, deletion, properties, size/hash and storage analysis through normal menus, shortcuts and APIs. Directories merge without deleting the destination; file conflicts remain explicit.
2. Moves within a share use checked server-side rename. Batch rename supports name swaps and interruption records; stale requests cannot act on recreated paths.
3. Unoverwritten copy/move/merge operations support identity-bound undo/redo. New descendants, replaced objects or changed redo sources are preserved. Remote deletion is not the local Recycle Bin; old servers without commit proofs do not advertise unsafe undo.
4. Browse, verify and extract remote archives, including split volumes, with real conflict checks. Archive creation, media conversion and Markdown-to-PDF use owned workspaces before remote publication. RDP virtual clipboard staging never deletes the original before upload.
5. Owner-authorized Windows applications can use trusted HTTPS WebDAV paths. Fixed HTTP/2 authority validation for rename. Version/lock-bound edits can save; unconditional overwrites remain rejected. Revoked group authorization cannot auto-resurrect. Missing OS integration falls back to retained editable working copies with explicit checked save/save-as.
6. Mutation planning bypasses directory browsing caches, and upload identity proofs come from committed handles. Tasks retain detailed progress, cancellation and errors; failed writes are never automatically replayed.
7. Sync RHVideo server addresses and usernames without credentials or sessions, preserving active logins and detecting concurrent metadata edits.

OS integration remains subject to WebClient/server filesystem capabilities. No drivers, TLS downgrades or fabricated remote ACL/stream support. Symbolic links/reparse points are not followed and directories are never replaced wholesale. Update both the client and file-serving computer.
