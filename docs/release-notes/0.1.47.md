# RHFiles 0.1.47

## 中文

- Windows 集成新增「用 RHFiles 选文件」：浏览器上传图片等文件时，列表上会多出这个按钮。点击后**不再弹窗**，而是直接把 RHFiles 主窗口带到最前面，并在文件列表下方加一条确认栏——因为 RHFiles 自己的标签页、双窗格、目录树、搜索、预览和键盘操作本来就是这个功能最好的界面，再套一层弹窗反而挡视线、也更难找文件。
- 确认栏会开在对话框当前所在的文件夹，之后你可以用 RHFiles 的任何方式自由浏览。选好文件后点「选好了」（或「清除选择」「取消」）。文件夹不计入，只有文件会被送回。
- 确认栏只接受那个对话框真正接受的文件类型（从对话框自己的类型下拉框读出，不是猜的），类型不符的文件不会被提交，也就不会出现浏览器静默丢弃选择的情况。
- 浏览器原来的对话框全程保持打开，确认后选中的文件会直接写回它的「文件名」输入框并自动确定，上传照常完成；RHFiles 只是更好用的浏览和预览界面，不替代浏览器自己的对话框。
- 交接期间会自动隐藏那个总在最上面的位置列表，它不会再挡住 RHFiles；选完或取消后回到浏览器对话框，列表会照常自动出现（之前它会在过程中消失，只能重开选择框才能回来）。
- 交接期间重新点按钮等于「回到 RHFiles 继续选择」，不会重新导航、丢掉你已经选好的文件。
- 新增 5 项后端单元测试（扩展名筛选解析、本地化标签提取、多选路径引号拼接、绝对路径判定、会话生命周期与前端契约字段）以及 1 项默认忽略的真实浏览器端到端测试：在 Microsoft Edge 的上传选择器里把带空格的图片路径写进「文件名」输入框，断言写入内容与确定后选择器关闭。
- 由于 GUI 测试套件需要可见的 RHFiles 窗口，在无桌面会话里会静默拿不到结果，`scripts/verify-file-choice-picker.mjs` 用无头 Edge 加载真实的确认栏模块和样式（只桩掉 Tauri IPC 和 RHFiles 自己的选择读取），跑完 19 项检查：筛选与计数、确认栏显隐、确认/取消/续选整条链路、以及它不会覆盖文件列表。`node scripts/verify-file-choice-picker.mjs` 即可运行。
- 顺手修掉一个真 bug：确认栏读的是 `start_folder`，而后端按 camelCase 序列化成 `startFolder`，导致主窗口不会跳到对话框所在文件夹。现在有检查项守着。

## English

- The Windows integration gained **Choose files in RHFiles**. When a browser asks for a file—an image upload, for example—the companion list offers this button. It no longer opens a dialog: it brings the RHFiles main window to the front and adds a confirm bar under the file list. RHFiles' own tabs, panes, directory tree, search, preview and keyboard handling are already the best possible interface for this, and wrapping them in a modal only covered the view and made files harder to find.
- The bar opens in the folder the dialog is showing, and after that you browse however you like. Confirm with "Use these files", or clear/cancel. Folders are not counted; only files are sent back.
- The bar accepts only the file types that dialog really accepts (read from the dialog's own file-type entry, not guessed), so a file it would silently drop cannot be submitted.
- The browser's own dialog stays open the whole time. Confirming writes the chosen files straight into its File name field and accepts them, so the upload completes as usual; RHFiles is a better browsing and preview surface, not a replacement for the browser's dialog.
- While a hand-off is in progress the always-on-top location list hides itself instead of covering RHFiles, and it reappears as usual when you are back in the browser dialog. Previously it vanished mid-flow and only came back if the picker was reopened.
- Pressing the button again during a hand-off means "back to RHFiles to keep choosing": it does not re-navigate or discard the files you already selected.
- Added five backend unit tests (filter-pattern parsing, localized label extraction, multi-select path quoting, absolute-path validation, session lifecycle plus the frontend contract fields) and one ignored real-browser end-to-end test that writes a spaced image path into Microsoft Edge's upload picker File name field and asserts both the written value and that confirming closes the picker.
- Because the GUI suite needs a visible RHFiles window and silently yields no results on a session without a desktop, `scripts/verify-file-choice-picker.mjs` loads the real confirm bar module and stylesheet into headless Edge (stubbing only the Tauri IPC bridge and RHFiles' own selection reader) and runs 19 checks: filtering and counting, bar visibility, the confirm/cancel/resume paths, and that it never overlays the file list. Run it with `node scripts/verify-file-choice-picker.mjs`.
- Fixed a real bug found on the way: the bar read `start_folder` while the backend serializes that struct as camelCase (`startFolder`), so the main window never navigated to the dialog's folder. A check now guards it.
