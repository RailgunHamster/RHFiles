# RHFiles Windows 0.1.89

## 中文

1. 在原生播放器内直接切换“仅竖屏”；保留完整原队列，取消后还原顺序。少于两个可用竖屏视频时明确报错，不改写当前播放。图库保存筛选／片段选择；重开顺序模式按原版取消竖屏、恢复全长，速度和循环独立记忆。
2. 恢复图片、截图集合的进度条和收藏入口，支持拖动定位、Home／End、滚轮和横向触摸滑动。集合位置不再被误当作视频时间轴；跨页预览可直接收藏当前媒体，截图对应源视频；窄窗口下预览工具栏换行，控件保持可访问。
3. 关闭截图父预览时停止其子视频；独立预览标识拒绝迟到的旧返回，即使重新打开的是同一张截图，也不让旧事件跳转或关闭新预览。
4. 修复切换 RHVideo 服务器后复用的播放器窗口保留旧会话、无法继续控制的问题。迟到的旧会话状态不会覆盖新状态；写操作不转投旧服务器，也不自动重放。
5. 恢复点击截图本身从头播放源视频的操作，同时保留独立的“播放此刻”时间点跳转；相关界面操作均调用可枚举的结构化接口。
   图片快捷键改绑后旧键不再生效；关闭、普通图片和任务图片的状态接口返回有效 JSON。缺少时长元数据的全长视频不再误按短片段截断。
6. 新增原版竖屏筛选、集合进度函数的差分检查、真实横竖屏解码及指针／键盘／触摸回归。本版不把局部行为验收表述为全部 1:1 完成；安卓原生控制及首帧性能仍需继续对齐。
7. 补入原生画布输入路由及多视频分组滑杆／首尾定位；操作绑定当前解码输入，拒绝迟到事件。真实窗口物理输入仍待验收。
8. 修复切换后立即调整片段时，未知时长被误报跳转越界；在当前输入就绪后最多执行一次，超时或失败给出原因，不自动重试。
9. 多视频改回图库顺序去重取池，默认按比例自动分组、布局和播放声音；翻组保留逐项播放状态，重开仅恢复匹配组。补回静音、收藏、暂存标记；正常结束在同一输入内循环，不把加载失败变成无限重试。所有新增操作提供结构化接口，Windows／Android 同等行为及完整发行验收仍须分别确认。
10. 加严实际显示帧检查后，继续修复暂停视频翻组返回黑屏、循环后进度停在末尾的问题。暂停画面恢复有独立状态、15 秒预算及错误提示，保持静音、不展示过渡帧，不依赖界面计时器；新的定位或播放操作可接管，不重放旧恢复意图。

## English

1. Toggle portrait-only playback without losing the complete source queue. Reject pools with fewer than two portrait videos without changing playback. Preserve gallery choices; a fresh sequential start resets portrait filtering and restores full-length playback as in the reference, while speed and loop stay mode-specific.
2. Restore the image/screenshot collection scrubber, favorites, Home/End, wheel and horizontal touch navigation. Collection position is distinct from video time. Favorite the current preview across card pages; a screenshot targets its source video. Wrap preview tools in narrow windows so controls remain accessible.
3. Closing a parent screenshot preview also closes its child video. Bind returns to a unique preview instance so a delayed return cannot navigate or close a later preview of the same image.
4. Refresh the native player's session when reusing its window after switching servers. Reject late state from old sessions and keep writes on their explicit server, without automatic replay.
5. Restore screenshot-image clicks to play the source from the beginning while retaining the separate timestamp-play action. UI operations use enumerable, structured APIs.
   Remapped image shortcuts replace the old binding. Closed, catalog and task-image states remain valid JSON. Full-length playback with missing duration metadata no longer uses the short-segment cutoff.
6. Add differential checks against the reference portrait filter and collection scrubber plus real portrait/landscape and pointer/keyboard/touch acceptance. These checks do not establish complete parity; Android native controls and first-frame performance still require further work.
7. Route native-canvas input and add multi-video group seeking and first/last navigation. Bind intents to the current decoder input and reject stale events. Physical desktop input acceptance remains pending.
8. Do not misreport unknown duration as an out-of-range seek immediately after a switch. Consume a pending seek once when its input becomes ready, with a bounded deadline and visible terminal failure, without automatic retry.
9. Restore gallery-order deduplication, aspect-ratio grouping/layout and audible defaults for the multi-video player. Retain per-video state while paging, but only the matching group across fresh opens. Add mute, favorite and staged-delete controls. Repeat normal EOF in the same input without retrying failed loads. New controls expose structured APIs; Android parity and final-package acceptance remain separate requirements.
10. Strengthen displayed-frame acceptance and address blank paused cells after paging and a progress clock stuck at the previous EOF. Paused-frame restoration is silent, hides transitional frames, exposes progress/error state and has a 15-second deadline independent of UI timers. Explicit seek or resume supersedes the older restore intent without replaying it.
