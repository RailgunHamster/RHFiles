# RHFiles Windows 0.1.89

## 中文

1. 在原生播放器内直接切换“仅竖屏”；保留完整原队列，取消后还原顺序。少于两个可用竖屏视频时明确报错，不停止、重建或改写当前播放。各连播模式分别保存筛选、位置、速度和全长／片段选择。
2. 恢复图片、截图集合的进度条和收藏入口，支持拖动定位、Home／End、滚轮和横向触摸滑动。集合位置不再被误当作视频时间轴；跨页预览可直接收藏当前媒体，截图对应源视频；窄窗口下预览工具栏换行，控件保持可访问。
3. 关闭截图父预览时停止其子视频；独立预览标识拒绝迟到的旧返回，即使重新打开的是同一张截图，也不让旧事件跳转或关闭新预览。
4. 修复切换 RHVideo 服务器后复用的播放器窗口保留旧会话、无法继续控制的问题。迟到的旧会话状态不会覆盖新状态；写操作不转投旧服务器，也不自动重放。
5. 恢复点击截图本身从头播放源视频的操作，同时保留独立的“播放此刻”时间点跳转；相关界面操作均调用可枚举的结构化接口。
   图片快捷键改绑后旧键不再生效；关闭、普通图片和任务图片的状态接口返回有效 JSON。缺少时长元数据的全长视频不再误按短片段截断。
6. 新增原版竖屏筛选、集合进度函数的差分检查、真实横竖屏解码及指针／键盘／触摸回归。本版不把局部行为验收表述为全部 1:1 完成；安卓原生控制及首帧性能仍需继续对齐。

## English

1. Toggle portrait-only playback directly in the native player without losing the complete source queue. Reject pools with fewer than two playable portrait videos without changing the current input. Keep filter, cursor, speed and full-length/segment choices separate per playlist mode.
2. Restore the image/screenshot collection scrubber, favorites, Home/End, wheel and horizontal touch navigation. Collection position is distinct from video time. Favorite the current preview across card pages; a screenshot targets its source video. Wrap preview tools in narrow windows so controls remain accessible.
3. Closing a parent screenshot preview also closes its child video. Bind returns to a unique preview instance so a delayed return cannot navigate or close a later preview of the same image.
4. Refresh the native player's session when reusing its window after switching servers. Reject late state from old sessions and keep writes on their explicit server, without automatic replay.
5. Restore screenshot-image clicks to play the source from the beginning while retaining the separate timestamp-play action. UI operations use enumerable, structured APIs.
   Remapped image shortcuts replace the old binding. Closed, catalog and task-image states remain valid JSON. Full-length playback with missing duration metadata no longer uses the short-segment cutoff.
6. Add differential checks against the reference portrait filter and collection scrubber plus real portrait/landscape and pointer/keyboard/touch acceptance. These checks do not establish complete parity; Android native controls and first-frame performance still require further work.
