# RHFiles 0.1.63

## 中文

### 默认视图对齐资源管理器：隐藏项拆成三个独立判断

旧版的"是否隐藏"只由一个布尔值决定，而且 `is_hidden` 把两件不相关的事混在一起：Windows 的 `FILE_ATTRIBUTE_HIDDEN` 属性和"名字以 `.` 开头"这个传统约定；`FILE_ATTRIBUTE_SYSTEM`（受保护的操作系统文件）更是完全没看。结果是 RHFiles 会列出资源管理器根本不显示的条目——带隐藏属性的 `!!!!!xxx.eml`、`desktop.ini`、`My Music/My Pictures/My Videos` 都在列表里，而用户无法用资源管理器的任何设置对齐。

现在拆成三个独立标记，各管各的：

| 判断依据 | 默认 | 开关 |
|---|---|---|
| 名字以 `.` 开头（传统隐藏文件） | 显示 | 原来的"显示隐藏文件"UI：工具栏眼睛按钮、Ctrl+H、设置里第一项 |
| `FILE_ATTRIBUTE_HIDDEN` | 隐藏 | 设置 → 常规 → "显示带隐藏属性的文件" |
| `FILE_ATTRIBUTE_SYSTEM` | 隐藏 | 设置 → 常规 → "显示受保护的操作系统文件" |

- 默认状态就是**资源管理器的默认视图**：隐藏属性和系统属性都藏起来，`.git`、`.gitignore` 这类点号文件照旧显示。
- 后两个开关正好对应资源管理器的"隐藏的项目"和"隐藏受保护的操作系统文件"，可以在设置里随时打开。
- 老配置会平滑迁移：以前把"显示隐藏文件"关掉过的用户，点号文件仍然不显示；显式设置过新开关的以新开关为准。
- 判定在数据层就分开（`rhfiles-core` 的 `FileEntry` 增加 `is_system` / `is_dot`），目录列表、侧边树、面包屑下拉、地址建议、Everything 搜索、内置搜索和网络（FTP/SFTP/共享）结果都走同一套 `entryVisible()` 过滤。

GUI 测试套件新增两条用例覆盖默认值与三者的独立性（232 项全过）。

## English

### Default view now matches Explorer: hidden items split into three independent judgements

The old visibility model was a single boolean, and `is_hidden` conflated two unrelated notions: the Windows `FILE_ATTRIBUTE_HIDDEN` attribute and the traditional "name starts with a dot" convention. `FILE_ATTRIBUTE_SYSTEM` (protected operating system files) was ignored entirely. RHFiles therefore listed entries that Explorer never shows — hidden `!!!!!xxx.eml` files, `desktop.ini`, and the `My Music` / `My Pictures` / `My Videos` junctions — and no Explorer setting could be matched.

Visibility is now three independent judgements:

| Judgement | Default | Toggle |
|---|---|---|
| Name starts with `.` (traditional hidden file) | shown | the historical "show hidden items" UI: toolbar eye button, Ctrl+H, first Settings row |
| `FILE_ATTRIBUTE_HIDDEN` | hidden | Settings → General → "Show items with the hidden attribute" |
| `FILE_ATTRIBUTE_SYSTEM` | hidden | Settings → General → "Show protected operating system files" |

- The default state is **Explorer's default view**: hidden and system attributes stay hidden, while dot-prefixed files such as `.git` and `.gitignore` keep showing.
- The two new switches mirror Explorer's "Hidden items" and "Hide protected operating system files" check boxes and can be flipped at any time.
- Existing profiles migrate cleanly: anyone who had turned the old toggle off keeps dot-prefixed files hidden, and an explicit new setting always wins.
- The distinction lives in the data layer (`FileEntry` gains `is_system` / `is_dot` in `rhfiles-core`), so directory listings, the sidebar tree, breadcrumb dropdowns, address suggestions, Everything search, the built-in search, and network (FTP/SFTP/share) results all share one `entryVisible()` filter.

The GUI suite gained two cases covering the defaults and the independence of the three judgements (232 passed).
