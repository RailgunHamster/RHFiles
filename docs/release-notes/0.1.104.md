# RHFiles Windows 0.1.104
1. 支持直接运行 `.ps1` PowerShell 脚本：双击、回车或右键“打开” `.ps1` 文件时，使用 `powershell.exe -ExecutionPolicy Bypass -File <脚本>` 在脚本所在工作目录执行（不再默认用记事本打开）；右键菜单新增“使用 PowerShell 运行”、“在 PowerShell 中运行（保留窗口）”以及针对 `.ps1` / `.bat` / `.cmd` 的“以管理员身份运行”。
2. 修复 GitHub Actions CI 的三处报错：
   - 消除“在 Verso 中查看历史”与“生成为 PDF”子菜单共用 `.ctx-icon-document` 导致 `context-menu-layout.test.mjs` 选择器冲突；
   - 修复 `rhvideo-workbench.js` 初始图库加载无变更时排队 150ms 延迟保存，覆盖外部刚写入的偏好配置导致 `rhvideo-rules.test.mjs` 偶发失败；
   - 在 `release.yml` 上传步骤前复核是否已由本地发布完毕，避免本机发布与 CI 同时打包同一版本时因字节时间戳不同而报错。
## English
1. Added direct execution support for `.ps1` PowerShell scripts: opening a `.ps1` file runs `powershell.exe -ExecutionPolicy Bypass -File <script>` in the script's directory instead of opening Notepad. Added context-menu actions for `Run with PowerShell`, `Run in PowerShell (Keep Open)`, and elevated `Run as administrator` for `.ps1`, `.bat`, and `.cmd` scripts.
2. Fixed three GitHub Actions CI failures:
   - Replaced the duplicate `.ctx-icon-document` on `View History in Verso` so `context-menu-layout.test.mjs` uniquely targets the PDF submenu;
   - Prevented initial unchanged gallery loads in `rhvideo-workbench.js` from queuing a delayed preference write across reconnects (`rhvideo-rules.test.mjs`);
   - Added a pre-upload publication check in `release.yml` so concurrent local release uploads and tag-triggered CI runs do not collide.
