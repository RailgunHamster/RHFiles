# RHFiles 0.1.62

## 中文

### 「点位置后对话框只闪一下、还在原地」——根因与修复

截图里的操作是**跳转**（点右侧 `RHFiles 已打开位置` 里的条目，让 Windows 对话框跳过去），不是交付文件。闪一下说明焦点被抢过来了，但路径没写进地址栏，回车自然没效果。

根因与上次同源：**Chromium 用的是旧式 `GetOpenFileName` 对话框，它没有可用的地址栏，`Ctrl+L` 在那里不会聚焦任何可编辑控件**。于是路径被写到"当前有焦点的控件"（通常是文件列表，根本没有 ValuePattern）上，什么也没发生——但代码仍然返回成功。

修复：

1. **`#32770` 文件对话框改走文件名框**：把文件夹路径写进它的 File-name 字段（同时支持 1148/1152 两代控件 ID）再回车——这正是用户手动"输入路径回车"的导航方式，且**不需要前台窗口**（回车在对话框已置前时发送，否则退回 UIA 点击确认按钮）。
2. **不再假报成功**：导航后会**回读对话框当前文件夹**（最长等 2 秒），不是目标文件夹就返回错误。选择器会把它显示出来，而不是继续静默地"闪一下"。
3. 地址栏那条路仍保留给现代对话框（`IFileDialog` / 资源管理器）作为兜底。

因此现在的行为是：点一个位置 → 对话框跳过去；若跳不过去，右侧选择器会显示具体原因。

## English

### "The dialog just flashes and stays put" — root cause and fix

The screenshot shows the **navigation** gesture (clicking an entry in `RHFiles 已打开位置` on the right so the Windows dialog jumps there), not a file hand-off. The flash means the focus transition happened, but the path never reached the address bar, so Enter did nothing.

Same root cause as the previous round: **Chromium uses the legacy `GetOpenFileName` dialog, which has no usable address bar — `Ctrl+L` does not focus an editable control there.** The path was therefore written into whatever happened to be focused (usually the file list, which has no ValuePattern), nothing happened, and the code still reported success.

Fixes:

1. **`#32770` file dialogs now navigate through the File-name field**: the folder is written into it (both generations of control ids, 1148 and 1152) and confirmed with Enter — exactly the navigation a user performs by typing a path and pressing Enter, and it needs **no foreground window** (Enter is sent when the dialog is already in front, otherwise the UIA confirmation button is used).
2. **No more false success**: after navigating, the dialog's own folder is read back (up to 2 seconds) and a mismatch returns an error, which the picker displays — instead of another silent flash.
3. The address-bar route remains as a fallback for modern dialogs (`IFileDialog` / File Explorer).

So the behaviour is now: click a location → the dialog goes there; if it cannot, the picker on the right shows the concrete reason.
