# RHFiles 0.1.23

## 中文

- 修复 0.1.22 中实验性 Windows 集成在新版资源管理器里拦截快捷键后却不跳转的问题。RHFiles 现在按精确的前台窗口句柄通过 Windows Shell 导航，只改变用户正在操作的那个资源管理器窗口。
- 加固系统打开 / 保存对话框的地址输入：等待地址栏进入可编辑状态、显式全选原路径，并将目标明确作为文件夹提交；仍然不会占用或覆盖剪贴板。
- 新增真实 Windows 端到端回归：受控资源管理器会在两个唯一目录间往返；受控记事本会打开系统文件对话框、经 RHFiles 跳转目录，再仅凭文件名打开目标文件。测试结束只关闭测试创建的窗口和进程。

## English

- Fixed the experimental Windows integration from 0.1.22 intercepting its shortcut without navigating in current File Explorer. RHFiles now uses Windows Shell navigation tied to the exact foreground window handle, so only the Explorer window being used is changed.
- Hardened address entry in native Open/Save dialogs by waiting for the editable address field, explicitly selecting the old path, and submitting the target as a folder. The clipboard remains untouched.
- Added real Windows end-to-end coverage: a controlled Explorer window round-trips between unique folders, while a controlled Notepad Open dialog is redirected by RHFiles and then opens a target using only its basename. Cleanup is limited to test-owned windows and processes.
