# RHFiles Windows 0.1.101

1. 修复 RHFiles 设备根目录显示为空，但直接输入 `rh://设备名/D` 可以打开的问题。显式共享的盘符和文件夹入口不再继承 Windows 根目录的隐藏、系统属性；盘内文件仍遵循原有隐藏项设置，不改变权限。
2. 客户端兼容旧服务端返回的盘符属性，因此不必等所有电脑升级才能显示共享入口。服务端也修正同一问题，供其他客户端使用。
3. 更新 Windows 自动化测试以匹配当前 CNB 默认更新源、库内播放器和原生 Shell 拖拽。CI 保留原生拖拽的强制验证；私有 RHVideo 源码对照测试在本地以生成数据运行，公共 CI 明确标注源码不可用，不上传个人凭据或私有源码。
4. 修复 Windows 交换左右鼠标键后，原生拖拽把按住的主键误判为已松开的问题。测试驱动也按系统主键设置发送鼠标输入，不修改系统鼠标配置。
5. Windows SFTP 改用静态链接的 OpenSSL 后端，避开原 WinCNG 后端偶发密钥交换失败；保持主机指纹验证，不自动重试文件操作。

## English

1. Fixed empty RHFiles device roots when direct paths such as `rh://device/D` still worked. Explicit share entries no longer inherit hidden/system attributes from Windows volume roots. Descendants retain their visibility settings; permissions are unchanged.
2. The client also accepts share entries from older servers, so every computer need not be upgraded at once. The server corrects the same metadata for other clients.
3. Updated Windows automation for CNB defaults, library-hosted players and native Shell dragging. CI still requires native drag verification. Private RHVideo reference tests run locally with generated data; public CI explicitly reports unavailable private sources without uploading personal credentials or private code.
4. Fixed native dragging incorrectly treating the primary button as released when Windows mouse buttons are swapped. The test driver also honors the current primary-button setting without changing system mouse configuration.
5. Windows SFTP now uses statically linked OpenSSL to avoid intermittent WinCNG key-exchange failures. Host-key pinning remains enforced; file operations are not automatically retried.
