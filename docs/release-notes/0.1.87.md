# RHFiles Windows 0.1.87

## 中文

1. 修复 RHVideo 图片通道的并发拥塞：封面与视频使用独立额度，短时拥塞有数量、时间上限的排队，不立即将正常图片变为 503；不自动重放请求。
2. 根据文件头识别有效 WebP、PNG、JPEG 等图片，不依赖服务器或 Windows 的扩展名 MIME 注册；流式传输不丢失探测字节，并拒绝冒充图片的 HTML／JSON 错误页。
3. 点击单个视频始终播放点击的文件；“开始连播”才使用筛选、多选和分段队列。下一项预加载等待当前真实首帧，不抢占起播资源。
4. 循环重复当前视频／片段；连播由原生控制器推进，不依赖可能被后台节流的界面计时器。旧队列版本的延迟控制不会影响新目标，自动推进失败只显示错误、不反复重试。
5. 关闭单视频不再停止独立多视频窗口；修复多格实际音量串扰、预加载影响当前音量的问题。播放器支持返回媒体库，显示播放终态与循环状态。
6. 增加原始 0.1.86 发布包的体验回归、实际解码／音频输出／真实 RHVideo 服务测试，CI 开启原生播放用例。补充首帧诊断；这些测试不代表所有媒体库、网络或硬件的流畅度已经验收，撤回先前“完整 1:1 体验已完成”的结论。

## English

1. Separate cover and video concurrency budgets, with bounded backpressure instead of immediate local 503 failures. Requests are not automatically replayed.
2. Detect raster image signatures, including valid WebP served with generic MIME types. Preserve all inspected stream bytes and reject HTML/JSON masquerading as images.
3. Direct playback opens exactly the clicked file; explicit playlist playback applies selection/filter/segment settings. Preloading waits for the current video's actual first frame.
4. Repeat the current video/segment and advance playlists natively, independently of throttled UI timers. Revision guards reject stale controls; progression failures remain visible without retry loops.
5. Closing a single player preserves independent multi-video playback. Isolate actual per-player audio gain and silent preloading. Add a library return action and accurate playback/repeat states.
6. Add experience regressions against the original 0.1.86 portable, real decode/audio and isolated real-RHVideo-service tests; enable native playback coverage in Windows CI. Include first-frame diagnostics. These checks do not establish smooth performance across every library/network/device; the previous complete 1:1 experience acceptance is withdrawn.
