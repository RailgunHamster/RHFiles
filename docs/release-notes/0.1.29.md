# RHFiles 0.1.29

## 中文

- 修复把文件或文件夹拖向另一个标签页时，标签切换后拖拽立即失效的问题。RHFiles 现在会在切换期间保留 WebView2 的原生拖拽源；悬停切换到目标标签后，可以继续拖到该标签的空白处或子文件夹中再松手，目标路径也会正确使用新标签的位置。
- 加强拖拽回归测试，覆盖真实标签切换、文件列表重绘、拖拽源存活以及切换后完成投放的整条链路，同时继续覆盖直接投放到标签和跨窗口复制 / 移动选择。
- 为 VS Code、Visual Studio、CMD、PowerShell、Git Bash、VLC、PotPlayer、QQ、微信、飞书、Windows 分享、ZIP、7-Zip、Bandizip 和 WinRAR 加入各自易于辨认的小图标与克制的品牌色。
- 精简 Windows 文件窗口伴随栏：位置列表只显示文件夹名称和路径，不再重复显示文件夹图标、左右窗格、标签编号和固定状态；同时修复“在 RHFiles 里打开”成功一次后按钮永久停留在等待状态的问题。

## English

- Fixed file and folder drags being cancelled when hovering over another tab caused RHFiles to switch tabs. RHFiles now preserves WebView2's native drag source during the switch, so a drag can continue into the newly selected tab and be dropped on its background or a child folder, with the destination resolved from the new tab.
- Strengthened drag-and-drop regression coverage for the complete sequence: a real tab switch, file-list redraw, native drag-source survival, and the final drop after switching. Direct tab drops and cross-window copy / move choices remain covered as well.
- Added individually recognizable small icons and restrained brand colors for VS Code, Visual Studio, CMD, PowerShell, Git Bash, VLC, PotPlayer, QQ, WeChat, Feishu, Windows Share, ZIP, 7-Zip, Bandizip, and WinRAR.
- Simplified the Windows file-window companion list to show only each folder name and path, removing redundant folder icons, pane names, tab numbers, and pinned badges. Also fixed **Open in RHFiles** remaining permanently stuck in its waiting state after the first successful use.
