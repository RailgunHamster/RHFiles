# RHFiles Windows 0.1.78

## 中文

1. 文件服务的自动启动、已有设备权限和设备组权限开关改为点选即保存，移除单独的保存按钮。开启登录启动会同时开启服务恢复；关闭服务恢复会同时关闭登录启动。
2. 修复“允许新设备写入、重命名／永久删除”刷新后自动取消的问题。新设备默认权限独立保存在本机配置中，刷新、重启和重新启动文件服务后都会保留。
3. 自动保存会显示保存中、已保存或失败原因；失败时恢复上次成功保存的值。连续点击按顺序保存，重新打开设置会等待未完成的保存，不再用旧状态覆盖新选择，也不刷新整页或清空其他输入。
4. 新设备默认权限只影响之后生成的配对码和 WebDAV 专用账号，不修改已有设备、已有配对码或设备组的授权。保留启动共享、生成配对码、撤销授权及本机移除／手动恢复的显式操作和确认。
5. 新增本机命令行接口 `server.defaults`，可通过 `server.state` 的 `config.newDevicePermissions` 读取默认权限。新增快速切换、保存失败恢复、真实点击、服务重启与进程重启回归测试。

本次更新为 Windows 修复版；Android 最新版仍为 0.1.26，无需重新安装 APK。设备组兼容性保持不变。

## English

1. File-service startup, paired-device grants and device-group grants now save immediately when toggled, without separate Save buttons. Enabling login startup also enables service restore; disabling restore disables login startup.
2. Fix new-device write/rename and permanent-delete defaults resetting after refresh. Defaults persist independently in the local service configuration across refresh, process relaunch and listener restart.
3. Inline saving/saved/error feedback with rollback to the last successful state. Rapid changes are serialized, reopening settings waits for pending writes, and saving no longer rebuilds the form or clears unrelated drafts.
4. Defaults apply only to future pairing codes and WebDAV credentials, never existing devices, pairing codes or groups. Starting sharing, pairing, revoking and local removal/restoration remain explicit operations with their existing confirmation rules.
5. Add the local `server.defaults` automation action and `server.state` → `config.newDevicePermissions`, with regression coverage for rapid changes, failure rollback, real clicks and service/process restarts.

This is a Windows maintenance update. Android remains at 0.1.26; no APK reinstall is required and device-group compatibility is unchanged.
