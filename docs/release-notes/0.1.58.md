# RHFiles 0.1.58

## 中文

- **修好 CDP（DevTools 协议）连不上**——这是"界面问题测不出来"的根源：
  - 原因：wry **总是**设置 `CoreWebView2EnvironmentOptions::AdditionalBrowserArguments`（没给自定义参数时会写入它自己的默认值），而 WebView2 规定**该属性一旦被程序化设置，`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 环境变量就被忽略**。所以按常规办法导出环境变量永远开不了调试端口，`chrome://inspect` 与 DevTools 协议都连不上。
  - 现在：设置 `RHFILES_CDP_PORT=9222` 后，端口通过 wry 使用的同一条通道注入（在 `Builder::build` 之前写进内存中的窗口配置）；手工创建的窗口（伴随选择器、恢复的额外窗口）也套用同一份参数——同一用户数据目录下所有 WebView2 环境的选项必须一致。**不设置该变量时行为完全不变，也不会打开任何端口**。
- **新增 `scripts/cdp-window.mjs`**：`targets` 列出窗口、`eval` 求值、`dom` 打印带尺寸的 DOM 大纲、`shot` 截图。有了它，**没有可见桌面也能看到并驱动真实界面**（配合读图即可直接检查布局）。
- **`scripts/test-gui.ps1 -CdpPort 9222`**：无桌面/远程会话下也能跑完整内置测试套件；结果文件没出现时会自动改用 CDP 调用 `window.__runTests()`。默认（隐藏窗口）模式在无桌面会话里永远不会初始化 WebView，这正是以前"测试没有任何结果"的原因。
- **修好内置测试套件本身的三处缺陷**（套件此前一跑到"确认栏"测试就抛异常中止，因此 231 项从未完整跑过）：
  - `serveFileChoiceSession` 引用了未定义的 `originalCall`，导致 `ReferenceError`；
  - 记录投递结果的桩代码根本没写，`window.__rhfilesLastChosenFiles` 永远是 `null`；
  - 夹具依赖"当前目录恰好有图片"，在没有图片的目录里必然失败；现在夹具自带图片文件并在结束时还原。
- **确认栏新增真实几何断言**（在真实窗口里测量）：整宽、位于窗格下方、是细条、窗格未被压缩——"确认栏变成半屏空列"这类问题今后会被直接测出来。
- 新增 `docs/DEBUGGING.md`，完整记录上述排查结论与用法。
- 新增单元测试覆盖 `RHFILES_CDP_PORT` 的解析（拒绝 0、空值、URL、越界端口）。

## English

- **Fixed why the DevTools protocol could not connect** — the reason UI problems shipped untested:
  - Cause: wry **always** sets `CoreWebView2EnvironmentOptions::AdditionalBrowserArguments` (falling back to its own defaults), and WebView2 ignores the `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` environment variable **once that property is set**. Exporting the variable therefore never opened a debugging port, so neither `chrome://inspect` nor CDP could reach a window.
  - Now: setting `RHFILES_CDP_PORT=9222` forwards the port through the same channel wry uses (into the in-memory window config before `Builder::build`), and hand-built windows (companion picker, restored extra windows) get the same value — WebView2 requires identical options for every environment sharing a user-data folder. **Without the variable nothing changes and no port is opened.**
- **New `scripts/cdp-window.mjs`**: `targets` lists windows, `eval` evaluates, `dom` prints a DOM outline with sizes, `shot` captures a screenshot — so the real UI can be seen and driven **without a visible desktop**.
- **`scripts/test-gui.ps1 -CdpPort 9222`** runs the full in-app suite on a headless or disconnected session; if the results file never appears it drives `window.__runTests()` over CDP instead. The default hidden-window mode never initialises a WebView there, which is exactly why the suite used to produce no results at all.
- **Fixed three defects in the in-app suite itself** (it threw as soon as it reached the confirm-bar test, so its 231 tests had never completed):
  - `serveFileChoiceSession` referenced an undefined `originalCall` (`ReferenceError`);
  - the stub that records the delivered files was never written, so `window.__rhfilesLastChosenFiles` stayed `null`;
  - the fixture assumed the visible folder contained an image and failed anywhere else; it now carries its own image entries and restores them afterwards.
- **The confirm bar gained real geometry assertions** measured in the live window: full width, below the panes, a thin strip, panes not squeezed — so a bar that turns into a mostly empty column is caught by the suite from now on.
- Added `docs/DEBUGGING.md` documenting all of the above, and a unit test for `RHFILES_CDP_PORT` parsing (rejects 0, empty, URLs and out-of-range ports).
