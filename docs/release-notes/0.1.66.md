# RHFiles 0.1.66

## 中文

- 修复重命名到已有文件夹时可能删除目标内容的问题。现在明确提供“合并文件夹”，保留两边独有的内容，内部同名文件单独询问处理方式。取消、跳过和保留两者均不会删除已有目标文件夹。
- 后端拒绝用普通 `overwrite=true` 替换整个目录。整目录替换需要单独的 `replaceDirectory=true` 授权；“应用于所有”的文件覆盖选择不会授权删除后续文件夹。复制期间目标类型发生变化时也会再次检查。
- 重命名冲突不再先删除目标，再尝试重命名。明确替换时使用现有的分阶段传输和失败回滚流程；旧复制、移动接口同样拒绝隐式覆盖已有目标。
- 新增文件夹冲突业务测试，覆盖重命名、复制、剪切、拖拽、Windows 文件剪贴板、冲突选择、撤销和重做，并直接验证后端保护。
- 复核 ZIP 目录层级：多层目录、同名文件、空目录、中文名称和父子重叠选择通过独立 7-Zip 解压验证。

## English

- Renaming a folder to an existing folder now offers **Merge folders**, retaining destination-only contents and resolving duplicate files individually. Cancel, Skip and Keep Both preserve the existing destination.
- The backend rejects whole-directory replacement with ordinary `overwrite=true`. It requires the separate `replaceDirectory=true` authorization. Apply-to-all file decisions do not authorize deleting subsequent directories; destination types are checked again when committing a staged transfer.
- Rename conflicts no longer delete the destination before attempting the rename. Explicit replacement uses staged transfers and rollback. Legacy copy and move commands also refuse implicit replacement.
- Added file-manager business coverage for rename, copy, cut, drag, native Windows file clipboard, conflict choices, undo/redo and direct backend safety checks.
- Rechecked ZIP hierarchy with independent 7-Zip extraction, including nested directories, duplicate leaf names, empty folders, Unicode names and overlapping parent/child selections.
