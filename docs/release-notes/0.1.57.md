# RHFiles 0.1.57

## 中文

- **修好「用 RHFiles 选文件」的界面错位**：确认栏之前被追加到 `#main-area`，而它是**横向** flex 容器（窗格 + 右侧检查器），于是这条栏变成了一个**竖列**——实测占到半屏宽、678px 高、绝大部分空白，按钮被挤在里面；窗格也被压掉一半。现在它挂在 `#app` 末尾（`.body` 之后），是真正的整宽底栏：实测 1256×47，位于窗格下方，窗格保持原宽。
- **无头校验脚本升级为真实布局测量**：此前它只在空白页里检查 `position/display`，根本抓不到这个问题。现在它加载**真实的 `index.html` DOM 与全部线上样式表**（仅去掉需要 Tauri 的脚本），再断言条栏「整宽 / 位于窗格之下 / 是细条 / 窗格未被压缩 / 按钮横向排列」。修复前后各跑一次：修复前 5 项几何断言全部失败，修复后全部通过（共 24 项检查）。
- 投递失败时确认栏原本就会显示具体原因（例如「Windows 未允许浏览器对话框重新获得焦点」或「无法把选中的文件写入浏览器对话框」），本次未改动该路径，但请留意栏内提示——它会指出失败在哪一步。

## English

- **Fixed the "choose files in RHFiles" layout**: the confirm bar was appended to `#main-area`, a **row** flex container (panes + inspector), so the bar became a **column** — measured at half the window width, 678px tall and mostly empty, with the buttons squeezed inside, while the panes lost half their width. It now lives at the end of `#app` (after `.body`), a real full-width bottom strip: measured 1256×47, below the panes, with the panes keeping their width.
- **The headless verification script now measures real layout**: it previously only checked `position`/`display` on a blank page, which is why this shipped. It now loads the **real `index.html` DOM and every shipped stylesheet** (app scripts stripped, since they need Tauri) and asserts the bar is full-width, below the panes, a thin strip, does not squeeze the panes, and lays its buttons out in a row. Run against the old code, all five geometry assertions failed; after the fix they pass (24 checks in total).
- Delivery failures were already surfaced inside the bar (for example "Windows did not allow the browser file dialog to regain focus" or "Unable to write the selected files into the browser dialog"). That path is unchanged, but the message tells you which step failed.
