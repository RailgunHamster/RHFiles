# RHFiles 0.1.50

## 中文

- **加密压缩包支持**。0.1.49 的报错定位到了根因：`vamzhb` 这类带密码的分卷 ZIP 是逐文件加密（文件名不加密，所以能正常浏览列表），而 7-Zip 拿到空密码后对全部 23,678 个加密条目报"Wrong password"。现在：
  - 右键解压遇到密码错误时，会弹出**密码输入框**，输入后自动重试（最多 3 次尝试）；取消则如实显示原始错误。
  - 双击浏览加密压缩包后，列表条目带加密标记，「全部解压」和单文件解压会在开始前就主动询问密码。
  - 密码作为单个参数传给 7-Zip（`-p` 紧贴密码），含空格、`-` 开头等特殊字符都按字面传递。
- 后端 `extract_archive` / `extract_7z` 新增可选 `password` 参数；未提供密码时仍传空 `-p`，保证加密包快速报"Wrong password"而不是挂起等待交互输入。
- 压缩包列表新增每条目的加密状态（来自 7-Zip 的 `Encrypted` 字段）。
- 新增单元测试：密码参数拼接（含特殊字符）、列表加密标记解析；并以真实 7-Zip 进程验证"正确密码可解出内容、错误密码的错误文本可被前端识别"。

## English

- **Encrypted archive support**. The 0.1.49 diagnostics pinpointed the root cause: password-protected split ZIPs like `vamzhb` encrypt file data but not names (so browsing worked), and 7-Zip with an empty password failed all 23,678 encrypted entries with "Wrong password". Now:
  - Context-menu extraction pops a **password prompt** on password errors and retries automatically (up to 3 attempts); cancelling shows the original error.
  - Browsing an encrypted archive marks entries, and "Extract all" / single-entry extraction ask for the password up front.
  - The password is passed to 7-Zip as one glued `-p<password>` argument, so spaces and leading `-` survive verbatim.
- The backend `extract_archive` / `extract_7z` commands accept an optional `password`; without one the empty `-p` is still passed so encrypted archives fail fast with "Wrong password" instead of hanging on a prompt.
- Archive listings now carry a per-entry encrypted flag (from 7-Zip's `Encrypted` field).
- Added unit tests for password argument building (including special characters) and encrypted-flag parsing, plus a real 7-Zip process check that a correct password extracts content and a wrong password produces text the frontend recognizes.
