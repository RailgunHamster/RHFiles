# Windows 资源管理器访问 RHFiles

RHFiles 设备入口（默认 `39128`）继续使用设备证书和设备组握手，不直接交给 Windows 网络位置向导。

1. 服务器和客户端先加入同一设备组；在服务器为该组启用文件服务。
2. 服务器已连接 Tailscale 后，在「设置 → 文件服务 → 资源管理器 · WebDAV」启用可信 HTTPS 兼容入口。首次申请证书会公开本机的 `ts.net` 域名，不公开文件或密码。
3. 使用界面显示的地址，例如 `https://winserver.taile71e4.ts.net:39129/dav/`。默认兼容端口是 `39129`，与原有设备组端口不同。
4. 在服务器选择客户端所属的组和成员，生成兼容凭据。在 Windows「添加网络位置」中填写地址和这组用户名、密码，不是 Windows 登录密码。

客户端需要 Windows WebClient 组件；设置内可检查本机状态。RHFiles 不会安装组件、导入根证书、修改 BasicAuthLevel、关闭证书校验或开放公网接口。Windows Server 可能没有安装 WebClient，仍可用 RHFiles 的设备浏览器访问。

兼容授权依附本机已经接受的设备组成员，不是独立配对。密码只显示一次，服务器只保存摘要，不参与 WebDAV 配置同步。重新生成会撤销旧凭据。移除成员、删除组后立即失效，手动恢复或重新加入也不会复活旧凭据；需要重新生成。

证书在每次启动文件服务时检查/续期；长期不退出的服务器应定期重新启动 RHFiles 文件服务以检查证书更新。续期失败只影响兼容入口，不能绕过证书错误，原设备组入口不受影响。兼容入口只接受本机、局域网和 Tailscale 网段来源，并只绑定这些本机接口。它不改变 Tailscale 自身的 ACL 或设备授权。

RHFiles 内的普通文件操作直接使用设备接口，不要求安装 WebClient。只有把远端路径交给 Windows 资源管理器、终端或其他本地程序时，才需要这个兼容入口。服务器首次为该成员生成兼容凭据后，RHFiles 客户端可以申请专属的系统接入凭据；它保存在当前用户、当前配置的 Windows 加密凭据文件中，不发到渲染页面、不参与配置同步。撤销成员的兼容授权后，客户端不能自行重新申请，必须由服务器再次授权。

文件夹始终合并，不能整体覆盖。WebDAV 的 COPY/MOVE 不覆盖任何已存在目标；请在 RHFiles 内完成需要冲突选择的替换。编辑已有文件时，PUT 必须携带匹配的强 ETag（If-Match），或该身份持有的独占文件锁；目标发生变化会拒绝保存，不会盲目覆盖。没有版本条件的直接覆盖会返回 428，需要重新读取文件。远端替换和安全移动要求对方也升级到支持条件操作的版本。

「设备组 → 连接诊断」记录 Windows 组件、服务能力、名称解析、凭据、HTTPS 探测和系统连接各阶段的结果。服务器的 `server.webdavCompatibility` 接口也提供最近的有界失败记录；不会记录密码、Authorization 或文件锁令牌。Windows WebClient 自身的大小/超时限制仍然适用，RHFiles 不自动修改系统注册表；大文件传输应使用 RHFiles 原生复制粘贴。
